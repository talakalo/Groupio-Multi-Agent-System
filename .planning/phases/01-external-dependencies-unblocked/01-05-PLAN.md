    ### D-02 routing clarification (important)

    D-02 reads "path-based routing, no subdomains". After research, this rule applies to
    the **user-facing frontend only**:

    | Component | Hosting | URL |
    |-----------|---------|-----|
    | apps/web (resident + contractor portal) | Vercel | `https://groupio.co.il` |
    | apps/admin (admin dashboard) | Vercel (path rewrite from apps/web project, see below) | `https://groupio.co.il/admin` |
    | FastAPI backend | VPS (Hetzner — per BACKEND.md) | `https://api.groupio.co.il` |

    Vercel cannot host the FastAPI backend (it requires a long-running Uvicorn process,
    not a serverless function). Path-based routing of `/api/*` from Vercel through to a
    VPS would require a Vercel rewrite, which adds latency and complicates WebSocket
    upgrade handling. Keeping the backend on the dedicated subdomain `api.groupio.co.il`
    is therefore the practical interpretation of D-02. The existing CI health check at
    `.github/workflows/deploy.yml` line 163 already targets this subdomain and **does
    not need to change**.

    Verification that the existing health-check URL is unchanged:
    ```bash

    # Expect: line 163 matches.
    ```

    ### Step 1 — Domain availability check

    Use any ISOC-IL accredited registrar's WHOIS or visit https://isoc.org.il and search
    for `groupio.co.il`. If the domain is already taken, the user must pick a different
    name and update D-01 in `01-CONTEXT.md` before proceeding.

    ### Step 2 — Domain registration

    Per D-04, register through an ISOC-IL accredited registrar. The current ISOC-IL list
    is at https://en.isoc.org.il/domains/accredited_registrars.html. Common options:

    | Registrar | Notes |
    |-----------|-------|
    | Name.co.il | Israeli, Hebrew UI, supports company registration number entry |
    | Domains.co.il | Israeli, English UI |
    | GoDaddy Israel | International with Israeli reseller |
    | Namecheap | International (also accredited via reseller path) |

    Documents/data required for `.co.il`:

    - **Israeli company registration number (מספר חברה רשום) or business registration
      number (osek morsche / osek patur).** This is `.co.il`-specific and is enforced
      by ISOC-IL — the registrar will ask for it.
    - Contact name, address, phone, email.
    - **Registration period: 1 or 2 years** (ISOC-IL maximum). Set up auto-renew.

    Cost: typically ₪50–₪120/year depending on registrar. Phase-1-acceptable budget
    item.

    Record in the Submission Tracker at the top of this runbook:
    - Registrar name + reference / order ID.
    - Registration date and renewal date.

    ### Step 3 — DNS records at the registrar

    Set these records at the registrar's DNS panel. **TTL 60 seconds is intentional** —
    short TTL during initial setup so DNS changes propagate quickly; raise to 3600 once
    everything is verified working.

    | Type  | Name | Value                  | TTL | Purpose |
    |-------|------|------------------------|-----|---------|
    | A     | @    | 76.76.21.21            | 60  | Apex domain -> Vercel apex IP |
    | CNAME | www  | cname.vercel-dns.com   | 60  | www subdomain -> Vercel |
    | A     | api  | <Hetzner VPS public IP> | 60  | Backend API subdomain (kept per D-02 clarification above) |

    Replace `<Hetzner VPS public IP>` with the actual production VPS IP — recorded in
    the same secret store that holds `DEPLOY_HOST` for the GitHub Actions deploy
    workflow. If the IP is unknown, retrieve it from the deploy-target host before the
    DNS change.

    ### Step 4 — Add the domain in Vercel

    1. Sign in at https://vercel.com.
    2. Open the **apps/web** project -> **Settings** -> **Domains** -> **Add**.
    3. Enter `groupio.co.il`. Vercel verifies the A record automatically.
    4. Add `www.groupio.co.il` -> redirect to `groupio.co.il` (Vercel offers this option).
    5. Wait until both rows show **Valid Configuration** (DNS propagation: 24–48 hours
       worst case; usually under 1 hour).
    6. SSL is auto-provisioned by Vercel via Let's Encrypt within minutes of DNS
       verification — no manual action.

    ### Step 5 — apps/admin path rewrite (`groupio.co.il/admin`)

    Per D-03, the admin dashboard is also a Vercel project. To serve it under
    `groupio.co.il/admin` (per D-02's path-based decision), use a Next.js rewrite in the
    apps/web project:

    Add to `apps/web/next.config.js` (this is documented here for the operator;
    actual code change is out of Phase 1 scope and belongs in Phase 8 admin-ops work or
    a follow-up infra plan):

    ```js
    // apps/web/next.config.js — add to module.exports
    async rewrites() {
      return [
        {
          source: '/admin',
          destination: 'https://<apps-admin-vercel-deployment-url>/',
        },
        {
          source: '/admin/:path*',
          destination: 'https://<apps-admin-vercel-deployment-url>/:path*',
        },
      ];
    }
    ```

    For Phase 1: it is acceptable to leave the admin app on its Vercel preview URL and
    treat the rewrite as a post-Phase-1 follow-up. Record this in the Submission Tracker
    as "Admin app rewrite — deferred to Phase 8".

    ### Step 6 — Verification

    From any Internet-connected host once DNS has propagated:

    ```bash
    # 1. DNS resolves to Vercel
    dig +short groupio.co.il A
    # Expect: 76.76.21.21

    # 2. SSL is provisioned
    curl -I https://groupio.co.il
    # Expect: HTTP/2 200 (or 308 redirect to apex) and a Let's Encrypt certificate

    # 3. SSL certificate details
    openssl s_client -connect groupio.co.il:443 -servername groupio.co.il < /dev/null 2>/dev/null | openssl x509 -noout -subject -issuer
    # Expect: subject contains CN=groupio.co.il; issuer contains "Let's Encrypt"

    # 4. Backend API on subdomain still works (deploy.yml health check)
    curl -fsS https://api.groupio.co.il/api/v1/health/live
    # Expect: 200 OK
    ```

    Mark the Submission Tracker rows ("Domain groupio.co.il registered", "Vercel DNS +
    SSL provisioned") as **Verified** with the date once all four checks pass.

    ### Risks and mitigations

    | Risk | Mitigation |
    |------|------------|
    | DNS propagation slower than 48 hours | Use TTL 60s during setup; switch to 3600s only after verification. If still failing after 72h, contact registrar. |
    | Vercel SSL fails to auto-provision | Most common cause: A record points elsewhere. Re-check `dig +short groupio.co.il A` returns exactly `76.76.21.21`. Vercel retries SSL every 6 hours. |
    | groupio.co.il already registered | User must pick alternative; update D-01 in CONTEXT.md and re-do all references. Out of scope for the runbook itself. |
    | Backend VPS IP changes | Update the `api` A record at the registrar; TTL 60s minimizes outage window. Document the VPS IP in the deployment secret store so the runbook owner can find it. |
    | apps/admin rewrite breaks admin auth (CORS / cookie domains) | Defer admin rewrite to Phase 8; admin remains on its Vercel preview URL during Phase 1. |

    ### Rollback

    Domain registration cannot be rolled back (registration fees are non-refundable
    after a few hours). DNS changes ARE rollback-able:

    1. To take groupio.co.il offline: delete the A record `@` -> 76.76.21.21 at the
       registrar. Allow TTL (60s) to expire. The domain stops resolving.
    2. To revert to a previous DNS state: restore the previous A record value.
    3. SSL rotation: Vercel reissues automatically once DNS resolves correctly again.
